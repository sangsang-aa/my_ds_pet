# 归档

这里放 **某个时间点的工程快照**，不是当前设计文档。当前设计看
[`../architecture/`](../architecture/README.md)。

## 规则

1. **只增不改**：已发布的归档不修改、不重写；发现错误时在文件末尾追加“勘误”，或新建下一份快照。
2. **命名**：`YYYY-MM-DD-<主题>.md`，例如 `2026-11-16-baseline.md`。
3. **一个快照对应一个可复现的 commit**：记录分支、完整 commit、构建命令、测试命令。
4. **区分“实测”与“推断”**：构建/测试/启动日志写实测；内存估算、未跑的路径明确标注。
5. **记录漂移**：文档说 A、代码做 B 的条目要保留证据（文件/符号/数值），不要只写“已过期”。
6. **不复制大段当前文档**：快照可以链接 `../architecture/`，但关键数值要自包含，避免链接目标变化后无法追溯。

## 模板

```markdown
# YYYY-MM-DD 基线：<主题>

## 元数据
- 仓库 / 分支 / commit / 日期
- 工作区状态（clean / dirty）
- 构建工具与版本

## 范围
本次快照覆盖哪些模块/资产；明确没覆盖什么。

## 功能矩阵
| 功能 | 状态 | 备注 |

## 资产清单
| 目录 | 连续帧 | bounds | 注册 | 备注 |

## 配置
关键默认值；是否存在 pet.ini。

## 构建与测试
- 命令、输出、产物大小/时间
- 测试结果（含新增测试）
- 未验证的构建路径

## 运行观察
- 启动日志
- 手工验证项
- 未验证项

## 文档漂移对照
| # | 文档位置 | 文档说法 | 代码/实测 | 影响 |

## 已知缺陷与限制
- 证据、影响、建议

## 下一步候选
- 不是承诺，只是当时判断的优先级
```
